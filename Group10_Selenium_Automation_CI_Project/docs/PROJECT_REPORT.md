# Mini Project Report — CampusTrack Selenium QA

## 1. Title
Automated Web Application Testing and Continuous Integration for a Student Attendance Management System.

## 2. Abstract
The project implements a college attendance-management web application and an automated browser testing suite that verifies core operations. Selenium WebDriver performs browser interactions, TestNG executes functional assertions, Maven manages Java dependencies, ExtentReports creates readable HTML evidence, and GitHub Actions runs the full suite on code pushes and pull requests. The demonstration includes intentionally introducing a search regression and observing automatic test failure.

## 3. Problem statement
QA teams repeatedly test role permissions, database operations, search, pagination, and file transfers manually after code changes. Human repetition is slow and prone to mistakes. An automated, repeatable test suite reduces repetitive checks and highlights regressions earlier.

## 4. Aim
To develop and execute automated web application test cases using Selenium WebDriver.

## 5. Objectives
- Develop a functioning management-system application with admin and normal-user roles.
- Automate authentication and server-side role restrictions.
- Verify CRUD and search operations using Selenium.
- Verify table contents and navigation between pages.
- Verify CSV upload and downloaded report contents.
- Execute the browser suite using TestNG and Maven.
- Create ExtentReports HTML reports with failure evidence.
- Automatically run the test suite in GitHub Actions after commits.
- Demonstrate a deliberately introduced bug being caught by the unchanged test suite.

## 6. System architecture
- **Web layer:** HTML, CSS, JavaScript interface.
- **Backend:** Python FastAPI routes, form authentication and REST endpoints.
- **Persistence:** SQLite with 25 seeded attendance records.
- **Browser automation:** Java Selenium WebDriver with a new browser per test.
- **Test orchestration:** TestNG annotations, assertions and suite XML; Maven Surefire execution.
- **Reporting:** ExtentReports HTML summary, Surefire results, screenshots on failures.
- **CI:** GitHub Actions using GitHub-hosted Ubuntu runner and headless Chrome.

## 7. Website modules
1. Separate administrator and student login portals with server-side role enforcement.
2. Attendance record creation, reading, updates and deletion.
3. Search and paginated records table.
4. CSV import and report download.
5. Admin-only console.
6. Read-only viewer dashboard.

## 8. Testing design
The suite has 18 Selenium test methods divided into four TestNG classes: `LoginRoleTests`, `CrudSearchTests`, `TablePaginationTests`, and `FileTransferTests`. Each test begins with a token-protected reset of the synthetic sample dataset and uses a separate Chrome session. This keeps test data independent. Test assertions verify not just clicks but observable results: changed table rows, HTTP 403, correct pagination, uploaded records, and downloaded file contents.

The Python API tests additionally verify validation and atomic CSV import behavior, server role checks, search and health. These are supporting checks and **do not replace** the Selenium requirement.

## 9. Demo methodology
1. Run the website and show normal application functions.
2. Run Selenium tests and show success in ExtentReports.
3. Push a code change switching `SEARCH_BUG_ENABLED` to True in `app/config.py`.
4. GitHub Actions executes the unchanged tests; `searchReturnsOnlyMatchingStudent` fails, and the pipeline flags the regression.
5. Restore the correct code and push; the tests should pass again.

## 10. Expected outcomes / evidence
Outputs are generated by real execution, not included as invented evidence:
- `target/extent-report/index.html` — test success/failure report.
- `target/surefire-reports/` — Maven/TestNG details.
- `target/screenshots/` — failed browser snapshots.
- GitHub Actions logs and downloadable artifacts — automated execution evidence.

## 11. Limitations
- Classroom sample credentials, limited authentication and no deployment-grade CSRF hardening.
- SQLite persistence and synthetic data, not an enterprise SIS.
- Selenium is sensitive to UI/DOM changes and browser availability.
- CI requires GitHub-hosted runner/network connectivity for dependencies.
- The intentionally broken feature is activated only to demonstrate real regression detection.

## 12. Future work
Move to more comprehensive access control and CSRF protection, add Firefox/Edge matrix testing, integration with staging deployments, parallel test execution with isolated databases, larger datasets, performance testing, and notification integration.
